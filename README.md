# Утро Ecovelle

Защищённая паролем сводка по товарам Ecovelle на Ozon и Wildberries. Сбор работает в GitHub Actions, готовая страница публикуется на GitHub Pages.

## Что исправлено

- Продажи и возвраты WB разделены по префиксу `saleID` (`S` / `R`). Возврат уменьшает предварительное начисление, независимо от исходного знака `forPay`.
- Денежные значения считаются в копейках/тиынах: дробная часть не теряется при округлении каждой записи.
- WB загружает все страницы по `lastChangeDate` до пустого ответа, а не только первую. Заказы сохраняются по `srid`, продажи/возвраты — по `saleID`; повторные выгрузки обновляют запись вместо удвоения цифр.
- Отменённый заказ остаётся в общем числе заказанных позиций. Доля отмен относится к той же группе заказов. Дата отмены WB хранится отдельно от даты заказа.
- Ozon: статус `delivered` относится к заказам, созданным в выбранные даты. Он больше не выдаётся за выкуп в день вручения. Выкупы и возвраты Ozon считаются по дате начисления, после сопоставления двух финансовых методов. Неподтверждённые количества отображаются прочерком.
- Данные за сегодняшний незавершённый день исключены. Даты Ozon с UTC смещаются в Москву; даты WB без смещения интерпретируются как московские. Расписание Actions остаётся прежним.
- Источники независимы. При сбое остаётся последний успешный снимок с датой и отметкой ошибки. Если оба основных источника заказов не обновились, публикация прерывается, прежняя страница остаётся доступна.
- Ошибка чтения существующей зашифрованной истории прерывает сбор: история не заменяется пустой.

## Интерфейс

Кнопки: вчера, последние 7 дней, последние 1 / 3 / 6 / 12 месяцев. Последняя дата — вчера включительно. Есть произвольный диапазон и календарный год. Сводка, графики, товары, география и CSV используют один диапазон. Сравнение — с непосредственно предшествующим отрезком такой же длины; оно отключается при пропусках истории.

Исторические суммы при пропусках показаны только по доступным дням и помечены как неполные. Отсутствующие дни не заполняются нулевыми продажами. Остатки, цены, отзывы и акции — снимки на дату сбора, они не являются историческими данными выбранного периода.

Графики показываются по дням до 45 дней, по отрезкам 7 дней до 180 дней, по месяцам для более длинных периодов. Wildberries идёт первым, Ozon — вторым во всех сводках, графиках, таблицах и CSV. Светлая/тёмная тема, мобильная версия, экспорт CSV. В географии Ozon показываются города, без предположения, что каждый город вне списка Казахстана относится к России.

## История и ограничения

`agent/history.enc.json` содержит зашифрованные минимальные записи и снимки. Он коммитится вместе со страницей; данные остаются доступными после очистки runner Actions. Используются AES-256-GCM, PBKDF2-SHA256 (600 000 итераций), случайные соль и IV. Открытые выгрузки не коммитятся.

Первый сбор WB запрашивает последние 89 завершённых дней плюс текущий. Далее обновляется минимум последняя неделя изменений, а прежние записи сохраняются. Если сбор отсутствовал дольше доступного API горизонта, разрыв остаётся явно обозначенным. История не ограничивается одним годом.

WB [гарантирует хранение оперативной истории не более 90 дней](https://dev.wildberries.ru/en/openapi/reports). Для квартала, полугодия и прошлых лет сразу после установки понадобятся архивные выгрузки. Импорт архивов в эту версию не включён: структуру нужно выбрать после просмотра реального файла. Оперативные `priceWithDisc` и `forPay` предварительные, могут изменяться и не равны окончательным суммам в отчёте реализации. «Предварительно начислено» не следует считать чистой прибылью или окончательной выплатой.

Ozon при первом успешном запуске запрашивает отправления за последние 24 месяца месячными окнами; далее обновляет последние 89 дней. Настройка `HISTORY_MONTHS` меняет глубину первоначального запроса. Доступность старых отправлений и действующих методов нужно проверить на вашем кабинете. Статусы более старых заказов после первичной загрузки сохраняются по последнему наблюдению.

Начисления Ozon **подключены**, доступ проверен на существующих ключах кабинета в Actions 12 октября 2026. Финансовые операции сохраняются в зашифрованной истории отдельно от заказов. Выкупы и возвраты относятся к дате начисления, которая может отличаться от даты вручения. Используются действующие методы:

- [Начисления за день](https://docs.ozon.ru/api/seller/#operation/GetFinanceAccrualByDay): `/v1/finance/accrual/by-day` возвращает общую сумму и валюту каждой операции, её идентификатор и дату начисления; доступны даты с 2022-01-01, пагинация через `last_id`. Историю можно собирать по дням и суммировать в выбранных периодах.
- [Начисления по отправлениям](https://docs.ozon.ru/api/seller/#operation/GetFinanceAccrualPostings): `/v1/finance/accrual/postings` принимает до 200 номеров, возвращает `quantity`, `sku`, `type_id`, `accrual_date`, сумму и валюту. Типы операций определяются через [справочник начислений](https://docs.ozon.ru/api/seller/#operation/GetFinanceAccrualTypes). Количество может быть `null`; нельзя считать все платные услуги отдельными выкупами или заменять дату начисления датой вручения.
- Старые `/v3/finance/transaction/list` и `/totals` помечены к отключению 2026-09-08 с переходом на эти три метода.
- Месячные [отчёты реализации](https://docs.ozon.ru/api/seller/#operation/FinanceAPI_GetRealizationReportV2) недоступны при договоре с ТОО «ОЗОН Маркетплейс Казахстан». Дневной [отчёт реализации](https://docs.ozon.ru/api/seller/#operation/FinanceAPI_GetRealizationByDayReportV1) требует Premium Plus/Pro и ограничен 32 днями.

«Начислено по кабинету» — сумма `total_amount` всех уникальных операций за дату, включая услуги, рекламу и корректировки всего кабинета. Вложенные комиссии не суммируются повторно. Заказы, выкупы и таблица товаров относятся к выбранным артикулам Ecovelle. Валюта начислений берётся непосредственно из API; смешанные валюты не складываются.

После ограничения 429 на больших партиях запросы количеств отправляются по одному номеру, до 400 номеров за запуск. Успешные партии сохраняются в зашифрованной истории даже при сбое следующей партии. Пропущенные количества повторно запрашиваются для последних дней и до 30 более ранних дат за запуск; новые недостающие номера имеют приоритет перед обновлением уже сохранённых. При повторном 429 финансового метода применяется дополнительная пауза 65–120 секунд с учётом Retry-After.

Количество определяется только для типа `SaleCommission` из действующего справочника: совпадают отправление, SKU, дата и величина итоговой комиссии или комиссии по прайс-листу; дополнительно сумма реализации (при необходимости с отдельными начислениями баллов/софинансирования той же валюты) сверяется с ценой за единицу × количеством. Если дневной метод не вернул цену, используется цена из подтверждённой товарной строки второго метода. Знак количества в строке возврата нормализуется; направление определяется суммой реализации. Положительная реализация — продажа, отрицательная — возврат. Одна строка комиссии не используется дважды. Логистика, обработка возврата и другие услуги не считаются товарными выкупами. При несопоставленном SKU, неизвестной цене/количестве или противоречии день отмечается как неподтверждённый; сумма начислений остаётся доступной.

Первый запуск загружает 7 последних полных дней и до 90 отсутствующих дат истории. Далее последние 7 дней обновляются, ещё до 90 старых дат добавляются за запуск; глубина определяется `HISTORY_MONTHS` (по умолчанию 24 месяца), минимум даты API — 2022-01-01. `OZON_FINANCE_BACKFILL_DAYS` меняет размер порции (1–180). Таким образом история за полгода/год заполняется постепенно, без превышения времени Actions. Покрытие начислений и подтверждённых количеств показано независимо от покрытия заказов; сегодняшние операции исключены. CSV использует те же даты и добавляет валюту/покрытие начислений и основание дат выкупов.

Диагностика **Actions → Утро Ecovelle → Run workflow → «Проверить доступ к начислениям Ozon без публикации сводки»** выполняет только чтение, без публикации. В журнал попадают общедоступные типы, схема полей и проверки соответствия, без API-ключей, сумм и номеров отправлений. Ограничение 429 учитывает `Retry-After`; при длительном ожидании сохраняется предыдущая история. Сверка итоговых сумм с выгрузкой личного кабинета остаётся отдельной проверкой: API и кабинет могут обновляться в разное время. Начисления, продажи и банковские выплаты — отдельные показатели.

Валюта Ozon берётся из `currency_code` товаров, когда она приходит. Если код отсутствует, используется `OZON_CURRENCY` (по умолчанию KZT, как в прежней версии) с явной отметкой. При обнаружении нескольких валют сумма заказов не показывается. WB в RUB. Разные валюты не складываются.

Отзывы показываются как **выборка** до 100 последних неотвеченных и 200 отвеченных, отфильтрованная за последние 30 дней; это не полная статистика всех отзывов.

## GitHub Actions

Нужны прежние secrets: `OZON_CLIENT_ID`, `OZON_API_KEY`, `WB_TOKEN`, `PAGE_PASS`. Пароль теперь также используется для истории. Не меняйте его без переноса существующей истории с прежнего пароля: иначе расшифровка прервёт сбор.

Для изменения оформления без повторных запросов API выберите в ручном запуске «Обновить только оформление из сохранённой зашифрованной истории». Этот режим требует уже созданную историю и сохраняет дату последнего сбора. В журнале сборки выводится REPORT_HEALTH: только состояния источников, наличие семи последних финансовых дат и причины неподтверждённых количеств; суммы и идентификаторы не выводятся.

Публикация Pages выполняется явно через `upload-pages-artifact` / `deploy-pages`: коммит от `GITHUB_TOKEN` сам по себе [не запускает сборку Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site). В артефакт входят только зашифрованный `index.html` и `robots.txt`, без открытых выгрузок. Настройка источника Pages и secrets не меняется. Сбор и восстановление разрешены только из `main`.

После внесения изменений в `main` запустите **Actions → Утро Ecovelle → Run workflow**. Проверьте журнал сбора и раздел «Состояние сбора данных» в отчёте. Первый запуск создаст историю и страницу. Без полноценного запуска с secrets сверка с вашим кабинетом не подтверждена.

Новый сбор заменяет прежнюю схему промежуточных `oz_raw.json`, `wb_raw.json` и `items_override.json`; это изменение формата хранения. Прежний `index.html` остаётся до успешного запуска. Возврат к старому коду должен сопровождаться его прежним workflow; старый сборщик новую историю не читает.

`setup_sync.sh` и `sync_github.sh` — прежний локальный механизм публикации. Для сервиса на Actions они не нужны. Если он включён на Mac, проверьте его перед переходом: он может опубликовать старую локальную страницу поверх результата Actions. Автоматически эти скрипты и LaunchAgents не менялись.

## Резервная копия и возврат

До внедрения создана [резервная ветка](https://github.com/ecovelle/utro/tree/codex/backup-before-redesign-2026-10-12) с исходным `main`: `d7a516789e7a8be6fc2d2120b7a73219b5254610`. Проверенное дерево: `9d0084e74282490ea2a23dd580e2d4b9cc151f6b`. Отдельно у владельца сохранены ZIP исходных файлов, Git bundle всей истории и контрольные суммы. В копии есть прежние код, workflow и зашифрованная страница. Secrets и настройки GitHub Pages находятся в GitHub, вне Git-архива; при обновлении они не меняются.

После внедрения возврат запускается так:

1. Откройте **Actions → Восстановить резервную копию → Run workflow**.
2. Выберите **main**, затем **Run workflow**. Дождитесь зелёного статуса и публикации Pages.
3. Откройте сводку: восстановится сохранённая страница; следующие запуски прежнего расписания обновят её старым сборщиком.

Восстановление выполняется новым коммитом без `force push`. Текущая версия и накопленная зашифрованная история сначала сохраняются в ветке `codex/before-rollback-…`. Скрипт проверяет совпадение дерева с резервной копией; при изменениях в main во время операции публикация отклоняется. Используется та же очередь `utro`, что у сборщика.

При возврате восстанавливается и прежний workflow; кнопка нового восстановления исчезнет. Копия и страховочная ветка останутся на GitHub. До внедрения кнопки ещё нет — рабочая версия уже соответствует исходному коду. Не запускайте восстановление только ради проверки на рабочем репозитории.

## Локальная проверка

Python 3.12+ и `cryptography`:

```sh
python3 -m pip install cryptography
python3 -m unittest discover -s tests -v
python3 scripts/make_demo.py
```

`preview/index.html` — демонстрация **только с вымышленными числами**, отдельно от рабочей страницы. Можно открыть файл в браузере. Пример полноценной проверки интерфейса при установленном Node.js, Playwright и Chrome:

```sh
PAGE_PASS=demo-only-password python3 agent/encrypt_page.py preview/index.html preview/encrypted.html
PLAYWRIGHT_PATH=/absolute/path/to/playwright node tests/browser_smoke.cjs
```

Проверяются периоды, выбор года, произвольные даты, экспорт, тёмная тема, экран 390 px, отсутствие источников, нулевые продажи и открытие страницы по паролю. Сервер и ключи маркетплейсов для тестов не нужны.
